# FrameScribe Library

**用 [FrameScribe](https://github.com/Jiangpip/FrameScribe) 把视频课程拆成带时间戳的章节大纲：能按视频里讲了什么来搜，点一下跳到原视频那一秒。**

🔎 **网站**：<https://jiangpip.github.io/FrameScribe-Library/>

## 现在有什么

| 课程 | 视频 |
|---|---|
| Ben Cloward - Advanced Materials | 41 |
| Ben Cloward - Procedural Content Generation (PCG) | 9 |

- **查**：在网站顶上的搜索框里搜（按 `/` 直接聚焦），比如「Fresnel」「视差」「PCG 样条」。结果列出视频和几分几秒，点一下就跳过去。
- **让 AI 查**：把网站地址给 Claude Code / Codex，让它先读 `llms.txt`。它会先看 `api/catalog.json`（课程 → 视频 → 章节），再只读需要的那一份 `api/videos/<id>.json`。

## 为什么做

想让学东西更方便一点。在数字时代，不该因为信息差学不到自己想学的东西，也不该把大量时间花在「找到底哪个视频讲了这个」上。

## 设想

如果很多人都把自己看过的视频用 AI 整理成这样的大纲，再汇到一起，找知识就不再只能靠标题和关键词，而是能按视频**里讲了什么**来找：搜一个概念，直接得到「哪个视频的第几分钟讲了它」。

## 难点

这件事真要做大，有几个绕不开的问题：

- **数据被弄脏**：有人上传错的、乱写的、恶意的大纲。需要审核、记录每条内容的来源、能随时回退。
- **维护量爆炸**：同一个视频被重复整理、质量参差不齐、量大到没人看得过来。需要去重、质量信号（比如看过的人打分）、分工维护。
- **钱**：内容多了以后，网站流量、存储、国内访问速度都要花钱。现在的网站是免费托管的，搜索要把整份索引下载到浏览器里；超过一两千个视频，就得把索引拆开或者换成服务器搜索。

所以**现在只由维护者整理收录，不开放随意投稿**。
